# Nuva OS 性能优化

> 本文档描述了应用于 Nuva OS 的性能优化措施及其测量或预期影响。

## 概述

Nuva OS 实施了多层性能优化策略，目标覆盖内核热路径：内存分配、IPC、调度和驱动管理。

## 1. Per-CPU 页面缓存 (PCP)

### 优化措施
- Order-0 页面分配绕过全局 Buddy 分配器自旋锁，通过维护每 CPU 空闲页面缓存。
- 高/低水位线控制自动补充和排空。
- 批量操作减少全局分配器锁竞争。

### 配置
| 参数 | 值 | 描述 |
|------|-----|------|
| `PCP_CACHE_SIZE` | 128 | 每缓存每阶页面数 |
| `PCP_HIGH` | 32 | 排空阈值 |
| `PCP_LOW` | 8 | 补充阈值 |
| `PCP_BATCH` | 16 | 批量操作大小 |
| `PCP_NR_ORDERS` | 3 | 缓存阶数 (4KB, 8KB, 16KB) |

### 预期提升
- Order-0 分配延迟：**降低 >= 15%**
- 缓存行对齐结构 (`#[repr(C, align(64))]`)

## 2. SLAB 分配器缓存行对齐

### 优化措施
- 所有 SLAB 对象大小对齐到 64 字节缓存行。
- 防止不同 CPU 访问的相邻对象之间的伪共享。
- `KmemCache` 结构本身缓存行对齐。

### 预期提升
- 热路径缓存命中率：**>= 90%**
- 减少跨 CPU 缓存一致性流量

## 3. IPC 快速路径优化

### 优化措施
- 小消息（<= 256 字节）使用内联/寄存器快速路径。
- 绕过共享内存映射，降低延迟关键 IPC 开销。
- SPSC 无锁队列，缓存行对齐槽位。

### 配置
| 参数 | 旧值 | 新值 | 描述 |
|------|------|------|------|
| `SMALL_MESSAGE_SIZE` | 64 B | 256 B | 寄存器快速路径阈值 |
| `MEDIUM_MESSAGE_SIZE` | 4 KB | 4 KB | 直接传输阈值 |

### 预期提升
- 小消息 IPC 延迟：**降低 >= 20%**
- 快速路径覆盖约 95% 的 IPC 消息

## 4. SpinLock 优化

### 优化措施
- 加锁/解锁集成抢占禁用，防止临界区内调度器调用导致死锁。
- 持有者 CPU 追踪，用于死锁检测。
- 热路径方法标记 `#[inline(always)]`。
- 架构特定 IRQ 安全锁（ARM64 DAIF、x86_64 RFLAGS、LA64 CRMD）。

### 预期提升
- 锁获取开销：**最小化**（单次 CAS + preempt_disable）
- 持锁期间上下文切换：**消除**

## 5. 原子操作内存序

### 优化措施
- 所有同步原子操作使用 `AcqRel` 内存序（之前不一致）。
- 统计计数器保留 `Relaxed` 内存序（无需同步）。
- 每个内存序选择附有注释说明理由。
- 修复 IPC zero_copy 中 `ref_count.fetch_sub` 从 `Release` 到 `AcqRel`。

### 预期提升
- 正确性提升（消除潜在的内存序错误）
- 无性能退化（AcqRel 是确保正确性的最低要求）

## 6. 热路径内联

### 策略
- `#[inline(always)]` 应用于：
  - `SpinLock::lock()`、`SpinLock::unlock()`、`SpinLock::try_lock()`
  - `preempt_disable()`、`preempt_enable()`、`preempt_count()`、`preemptible()`
  - `allocation_allowed()`
  - `PerCpuPageCache::alloc()`、`PerCpuPageCache::free()`
  - 所有原子操作包装函数
  - `SchedPolicyConfig` 参数访问器

- `#[inline]`（编译提示）应用于：
  - 可能受益于内联的非关键路径函数

### 监控
- 内联导致的内核镜像体积增长不得超过 5%。
- 如果超出，将非关键路径的 `#[inline(always)]` 降级为 `#[inline]`。

## 7. 声明式范式性能

### 驱动注册
- `DriverDescriptor` 为 `&'static` — 运行时零开销。
- 设备匹配使用预排序的优先级顺序。
- 驱动探测期间无堆分配。

### 电源状态机
- 当前状态存储在 `AtomicU8` 中 — 无锁读取。
- 状态转换验证为 O(n)，基于转换表（通常 <= 6 条记录）。
- `current_state()` 标记 `#[inline(always)]`。

### 调度器策略
- `SchedPolicyConfig` 每参数使用 `AtomicU32` — 无锁读取。
- 热更新是原子的，使用代际计数器防止 ABA 问题。
- 缓存行对齐以防止伪共享。

## 8. RCU（读-拷贝-更新）

### 优化措施
- 读取侧访问无锁且无等待
- 写入者创建新副本，使用 `synchronize_rcu()` 等待宽限期
- 目标用例：模块列表遍历、设备树查找、安全策略读取
- 读取路径开销：仅一次内存屏障

## 9. Per-CPU 基础设施

### 优化措施
- `PerCpuRunQueue` — 缓存行对齐的每 CPU 运行队列，无锁本地调度
- `PerCpuPageCache` — 每 CPU 空闲页面缓存，绕过全局 Buddy 锁
- Per-CPU 统计 — `AtomicU64` 计数器，`Relaxed` 内存序，按需聚合
- 所有 Per-CPU 数据：`#[repr(C, align(64))]` 防止伪共享

## 10. io_uring 异步 I/O

### 优化措施
- 通过用户空间和内核之间的共享环形缓冲区实现零拷贝 I/O
- 共享内存中的提交队列（SQ）和完成队列（CQ）
- 固定缓冲区注册避免每次 I/O 页面钉住
- 链接操作支持原子多步 I/O 序列
- 批量提交减少系统调用开销
